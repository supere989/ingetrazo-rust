# Shared owner payload admission and fallible preparation

The standalone private owner accepts an explicit shared OwnerBudget. RAII leases categorize History, Staging and Preparation. Multiple owners and active transactions share the same ledger and configured admission limit. A refused reservation changes no charge; dropping a consumed/refused candidate releases its lease. History delta leases survive Undo/Redo stack movement. Only an explicitly successful new branch, replacement or owner drop releases superseded history; there is no quota-driven history eviction. The default remains unlimited tracking, with no production configuration/admission enabled.

Constructor, replacement, Undo and Redo now prepare position arrays, adjacency maps/vectors and touched-ID sets with checked extents and fallible reserves before semantic writes. Revisions are checked before writes. Spatial-index preparation still validates exact ordered positions and installs by allocation-free swap. Prepared delta copies use fallible record/adjacency reserves. Existing major-container collect/clone allocations in these owner paths were removed. Legacy convenience begin() remains explicitly infallible; the controller uses try_begin().

Three actual focused tests pass: constructor/Undo/Redo/replacement refusal and state preservation; aggregate charges across concurrent transactions with staging/commit refusal and retry; and TWO owners sharing one budget, with preexisting history and Redo surviving a refused commit. They assert exact retained-history accounting, only consumed-candidate staging released, zero preparation after refusal, unaffected sibling owner, unchanged state token via still-valid transaction, and eventual zero ledger after explicit owner release. No simulated allocator OOM or VM rerun was used.

The admission ledger is a LOGICAL PAYLOAD policy, not an allocator-enforced physical-memory cap. Staging/preparation use conservative checked typed slots, table extents and key limb allowances. Retained History charges actual prepared record/adjacency capacities plus Delta headers. Excluded: application-owned live mesh/index and their reserve capacity, history Vec capacity slack, allocator overhead/fragmentation, ledger Rc allocation, error String allocation, actual BigInt key allocation failure, VM/compiler/native memory and externally prepared replacement meshes. BigInt conversion itself remains infallible; these exclusions prohibit a comprehensive recoverable OOM or process-memory claim. A lowered limit retains existing charges and refuses new work. Entry limits and retained-history payload caps remain separate policies.

VM dependency is optional in this standalone crate; default feature vm preserves the prior harness while owner-only checks avoid rebuilding the VM.
