# Exclusive prepared multi-owner publication

JournalOwner and FaceOwner now expose separate fallible `prepare` and allocation-free `apply` operations. Each prepared value holds an exclusive mutable borrow through publication, so another safe caller cannot change its owner between admission and application. Dropping it discards unpublished records and releases staging/preparation/history candidate charges. Existing commit is a convenience wrapper over the same path.

The focused fixture prepares two owners, refuses the second through actual shared logical budget admission, discards the first and verifies both geometry/history plus the first owner's preexisting Redo and all charges. It then prepares both successfully, applies both, rejects an earlier held transaction and exercises Undo/Redo. This repeats for face owners, including a face using only existing boundary geometry. An actual global allocator counter verifies zero allocations across both prepared edge applications and both prepared face applications. Final shared charges are zero. Existing twelve-state edge and face history reporters run through the changed wrapper and are retained.

This is a prerequisite for genuine editable VM Mesh publication across multiple touched objects. It does not route current VM Mesh payloads into these owners, implement general mutation rollback, include physical allocator/VM memory admission, or enable production scripting. Capacity changes during failed preparation are allowed; semantic geometry, tokens and history remain unchanged. Internal invariant assertions remain programmer-error boundaries, not universal panic recovery.
