# Genuine application recipe helpers (engineering opt-in)

`extrude`, `prism`, `revolve` and `wall` execute ported pinned `core.ai._recipe_helpers` definitions inside RustPython against the same genuine editable Mesh/Face/Edge and live Scene/Group graph. No CPython, subprocess geometry wrapper, alternate helper Mesh graph, image pass or provider request is introduced. A private native elementary-math module supplies only recipe operations; it does not make full `math`/stdlib imports available.

`_finish` preserves source color tuple evaluation per Face, prepares native outward winding before in-place reversal of persistent Face loop lists, executes the source 42-degree edge softening pass inside the fuelled VM, appends the returned genuine Group to the live Scene and publishes it through the actual console. One helper command can own group membership; held objects survive ordinary Undo/Redo and detached edits. Prepared orientation does not replace Face/Vertex identities or their persistent rings.

The focused actual pinned-source/app corpus has 13 complete immediate states: colored extrude, Undo/detached Face edit/Redo, slanted holed prism, smooth revolve, window/gable wall and its Undo/Redo, negative extrusion, command failure after adding a Group, and retained earlier Redo. Genuine returned Group/Mesh/Face/list identities are asserted. Eight altered complete observations (including boolean/integer type substitution) must fail the same validator. Every retained logical budget is zero after retirement/application teardown. The initial missing-math refusal and integer-only native hypot conversion refusal are retained; integer numeric-protocol conversion is corrected.

## Boundaries retained

This is an optional engineering consumer, not complete production scripting. `house` is the next recipe helper; arbitrary helper parameters, callbacks, source orientation/triangulation pathological cases, two-sided paint turnover and `Face.interior` partition projection remain required. The private native orientation entrypoint rejects those latter unsupported cases before ring mutation and aborts the staged command even when its exception is caught. It currently admits at most 2,048 faces; that is an explicit engineering restriction, not a valid-model production ceiling or a wall-time guarantee. Kernel scratch/native builtin allocations and arbitrary callback memory are not fully bounded.

The existing full group receipt packing, repeated whole-group comparison, root snapshots and app full-Scene Undo costs remain. Root Scene aliases/global adapters, transformed/nested/component Group slots, full stdlib and safe unrelated live-VM synchronization remain open. On failed commands the app retires its private scope and preserves the visible document/history; it does not claim preservation of all source globals/held aliases after errors or source partial-failure behavior. Rendering/Metal/GPU parity is outside this proof.
