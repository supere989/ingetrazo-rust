# Append-owned history proof

Twelve ordered states agree exactly with actual frozen core.ai.run_transactional/History: append, Undo, no-op retaining Redo, failed staged mutation retaining Redo, Redo, repeated Undo/Redo, branch replacement and unavailable Redo. Four same-validator mutations reject. Native history fixture invokes real MeshJournal/AppendUndo directly; genuine VM execution remains separately covered by the eight-script corpus. This is not a native production app history integration proof.

Delta stores only newly appended records, baseline UUID/position admission arrays and command state. Undo removes all transaction-created vertices (SnapshotImport semantics, unlike AddEdgeCommand orphan policy); Redo reinstates their UUIDs and edge order. No whole Mesh or Scene snapshot exists in command implementation. Seven focused tests include three exact repeated UUID restorations, external face ownership refusal, changed redo base refusal and earlier malformed/stale controls. Initial implementation cloned appended vertex records before filling adjacency; first two history tests failed with Changed append command ownership. Preparing new-vertex adjacency before retaining delta corrected that concrete failure.

Unrelated Scene state is outside this command, not a blanket global history exemption. Append-only admission excludes changing/deleting existing entities; metadata, context, command routing, lifetime generations, persistent proxy reattachment and complete journal remain required. Baseline admission/index rebuilding is once per transaction; ordinary allocations still prevent an all-OOM atomicity claim.
