# Independent acceptance protocol

The pinned Python-generated example files are the reference corpus. Run from the repository root after recursive submodule initialization:

```sh
cargo test --workspace --locked
cargo build --locked -p ingetrazo-cli
python3 scripts/check-document-parity.py
```

The document checker fails closed if any of the four named fixtures is absent. It recursively checks every original scene field, including component prototypes, group transforms, geometry coordinates, attributes, saved cameras and sheet metadata. Added defaults are tolerated; original list order and schema must survive. Numeric comparisons allow only 1e-10 relative/absolute rounding. Every non-document ZIP member must preserve its SHA-256 content hash. Unknown metadata is part of preservation acceptance. Five in-memory negative controls deliberately remove metadata/groups or corrupt geometry/transform/material; all must be detected. Comparison errors are retained as JSON paths.

This is untouched-document preservation, not a claim that preserved unknown data can be edited. An independent edited-save acceptance must modify modeled geometry/transforms, save, and establish both the edits and retained metadata. Python reopen, recursive instance expansion, texture rendering and GUI user workflows remain separate acceptance gates. The checker reads Python-format source documents independently of Rust serde but does not run the Python application.

`boolean_acceptance.rs` computes signed tetrahedron volume from boundary coordinates without calling the implementation volume/manifold methods. For overlapping unit boxes analytic union/difference/intersection volumes are 1.5/0.5/0.5. Oriented edge incidence independently checks closed output. Copy-A and concatenate-boundaries negative controls prove old placeholder geometry fails this oracle. This bounded corpus does not cover arbitrary curved, degenerate, rotated, material or undo cases.

CI distinguishes Rust tests/build from a separately named semantic document step; retained evidence uploads even on semantic failure. Baseline files retain observed losses and fake booleans before implementation repair. Red semantic acceptance is intentional while blockers remain; do not replace it with counts or silently skip examples.

## Original runtime reopen

`INGETRAZO_BINARY=target/debug/ingetrazo python scripts/check-python-reopen.py` runs the pinned original loader and serializer on both the source and Rust-roundtripped file. Install original runtime dependencies in an isolated environment; the retained Python freeze records the local run. Headless Qt uses offscreen mode and a temporary cache. Older sources lack group names and persistent UIDs, so the checker freezes only the original runtime generators at the start of each load. Existing stored names/UIDs remain authoritative. This removes nondeterministic original behavior without discarding identity fields from comparison. Original runtime scene geometry, annotations, composer and other serialized document data are compared recursively. This still does not establish rendered or interactive acceptance.

`check-python-edits.py` creates source documents, edits them in Rust, and verifies actual original-runtime geometry, persistent IDs and transforms. It also reopens fresh Rust saved views, section planes, geographic datum/points/paths and sheet layouts. Unknown source metadata is checked in saved JSON, since the original application itself omits opaque fields it cannot interpret.

`check-python-booleans.py` compares union, subtraction and intersection on overlapping, rotated and contained boxes (nine cases). Rust outputs are reopened by the pinned Python application. Both results pass through the original native manifold3d kernel; volumes and bidirectional difference volumes must agree within 1e-6 cubic metres. The rotated case differs by less than 1.4e-8 cubic metres due to the original QVector3D float precision. A copy-input negative control must disagree. This checks spatial solid equivalence rather than polygon counts or the Rust volume method. Rust uses manifold-rust; the independent original oracle uses native manifold3d. Degenerate/general geometry, attributes, picking and undo remain outside this bounded shape test.

`check-python-pushpull.py` compares the original tool classify/commit path against Rust outputs for cap extension, inward cap movement, blind pocket and through-cut. All four independently reopened solids have zero bidirectional native manifold difference. Original subtractive/orientation regression modules separately pass 42 tests; these establish the original oracle works, not that all 42 have Rust counterparts. The independent Rust cases also check hole rings/inner walls, nonfinite and invalid-face atomicity, and unrelated solid/wire preservation. Full original prism/recess/through-notch/slanted/instance corpus and interactive input remain open.

`check-python-followme.py` compares four connected sweep constructions (straight, 90 degree bend, holed tube and closed rectangular torus) against the original engine with zero bidirectional native manifold difference. A straight-result negative control disagrees with the bent shape. Original Follow Me/revolution reference modules separately pass 24 tests. Three independent Rust tests additionally cover branch rejection, malformed path atomicity and bent-path material propagation. Axis-touching/crossing revolution poles and full interactive selection remain open.

`check-python-components.py` verifies real Python object identity after Rust shared-definition serialization: linked instances reopen with the same mesh, plain groups remain independent, a registry edit updates both linked instances, Make Unique separates future updates, and persisted instance IDs and opaque attributes survive. This bounded definition probe does not cover recursive editor/clipboard/undo workflows.

The component checker also drives actual Rust GUI controller methods for nested editing: begin parent edit, begin child edit, modify local geometry, finish twice, save, undo/redo exact scene equality, attempt blocked fragment save, cancel exactly, Make Unique, edit, copy and paste. Original Python reopening verifies linked parent-child mesh identity, expected edited/undone geometry, isolated unique edits and linked clipboard placement with different UIDs. These are controller transactions; no screen gestures or visual nested-context acceptance is inferred.

`check-python-fillet.py` compares a convex box edge at radius/segments 0.2/8, 0.1/3 and 0.3/16 against the original native shape oracle. Spatial differences stay below 4.7e-9 cubic metres; unchanged softened-edge geometry is rejected in every case. Two independent Rust tests check cylinder tangent geometry, segment-controlled surface count and atomic rejection of invalid/excess radii. Original fillet reference module separately passes eight tests. Multi-edge rims and spherical corners have no Rust acceptance and remain open.

`check-exchange-exports.py` independently decodes OBJ and binary STL and uses ezdxf as an external DXF parser. A reflected nested holed surface must retain area 12, transformed bounds, correct hole occupancy across 256 spatial samples, hidden-object exclusion and +Z winding; STL normals must agree with geometric winding. An unholed rectangle negative control must fail. The pinned original OBJ/STL exports match spatial geometry but keep reflected open-face -Z winding; Rust +Z winding is an explicit correction, not an assertion of identical original winding. Retained baseline exports all lost the nested surface; corrected exporters pass all three format probes.

`audit-exchange-imports.py` remains a failing open-requirement audit outside the completion CI gate: named OBJ children and MTL face colors disappear; DXF metre LINE/LWPOLYLINE geometry and SITE layer disappear despite conversion exit 0. One STL touching-cube fixture preserves coordinates and the original-runtime solid report. This small successful STL case does not establish the whole importer corpus. Unsupported entities, units, textures and atomic failure remain open. Export geometry progress must not mark P22 Verified.

The OBJ export gate additionally checks sanitized named material references, MTL Kd and d values, all local affine per-vertex UVs after reflected nested placement, exact exported image hashes, original-runtime color-only reopening, and original-runtime texture/UV reopening. The original OBJ loader ignores MTL opacity d and textured Kd, so those fields are independently read from the MTL rather than claimed as original-loader behavior. A missing embedded asset must return an error while preserving existing OBJ and MTL destination bytes.

Expanded fillet acceptance includes a four-edge top rim and all twelve box edges with spherical joins. Both match original shape within 3.9e-8 cubic metres; an independent edge-incidence/orientation checker verifies closed boundaries and volume bounds. Arbitrary mixed/concave selections and interactive rounding remain outside these five shape cases.

Make Unique acceptance now includes an ordinary parent with a recursively isolated subtree. Later original shared-child edits must leave that unique subtree unchanged, while parent/child transforms and child UIDs stay stable. Classic unique clipboard copies are independent; copied linked components retain sharing with different placement IDs. The earlier linked expectation for copied unique leaves applied to the old implementation and has been corrected to match original `copy_group` behavior after materialization.

The FollowMe native original oracle now includes nine clipped-pole sphere revolutions (profile plane 0, 7.5, 33 degrees; profile/path radii 1/1, 0.5/1, 1/0.5), in addition to four path cases. Bidirectional native spatial difference, rather than face count, is the acceptance condition; arbitrary paths and gestures remain open.

`check-dxf-curves.py` checks sampled bidirectional distance against original curves (circle, arc, bulged polyline), with a 2.1 cm bound accommodating both independent 1 cm flattenings. It separately verifies block and non-Z OCS refusal without destination truncation. Explicit millimetre-to-metre import remains an open unit acceptance requirement; refusal controls do not establish block/OCS parity.

Independent `recovery_acceptance` launches a child test process, autosaves a named document edit, and terminates with exit37 without cleanup. A fresh app/session store recovers the changed vertex, retains original project bytes, restores persisted preferences, keeps the recovered document untitled/dirty, and rejects native close plus failed save until explicit discard. This checks Linux process liveness and egui viewport commands; it does not establish rendered platform-dialog or non-Linux PID behavior.

Independent manual FollowMe regression reproduces the original reference drag sequence: bridge a skipped edge, backtrack twice, extend again, reject skipped edges without mutation, and start a mid-edge crossing in either cursor direction. Original 24 FollowMe regressions still pass. This asserts path semantics, while worker controller tests cover preview/release; actual mouse gestures and rendered UX remain a separate acceptance boundary.

Independent Fillet controller regression additionally checks immutable preview/cursor radius 0.25 and cancellation, selected rim segment input6, negative radius refusal without geometry change, and committed0.15 tangent placement with selection cleared. Original kernel plus tool references11 pass offscreen. Actual rendered pointer/dialog behavior remains separate.

`check-python-clipboard.py` validates mixed selected holed face and loose attributed curve: immutable preview/cancel, one commit history step, exact undo/redo, original-runtime translated face/hole/wire positions, raw retained opaque fields, independent curve IDs, hidden/soft flags and affine UV offset correction. Same-plane merge, cross-context transforms and desktop system clipboard remain open.

The glTF independent decoder enforces original `formats/gltf.py` coordinate convention `(x,y,z) -> (x,z,-y)`, Y-up/right-handed/metres; decoded coordinates map back `(x,-z,y)` before world-space bounds/winding checks. Earlier raw-Z-up fixture acceptance was an insufficient export contract; `export-axis-baseline.txt` retains the resulting detected failure pending exporter correction.

`check-python-gltf-import.py` independently authors three external/data-URI/GLB variants, compares original imported world geometry and affine UV at vertices, and checks two shared mesh placements with reflected nested TRS, interleaved/strided normalized ushort UVs, KHR texture offset/scale, PBR opacity, explicit authored color and exact PNG bytes. Truncated accessor range/required Draco controls preserve an existing destination. The corrected export decoder also passes original Y-up positions/normals. Textured original importer drops PBR color, so that specific property uses authored input as oracle. These fixtures do not establish animation/rigging/DAE or general reference import parity.

`check-python-intersect.py` compares exact original segment coordinates for crossing squares, interrupted hole, coplanar non-crossing, and selected group against model.
