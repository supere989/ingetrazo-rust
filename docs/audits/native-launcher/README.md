# Normal launcher and efficient native rendering

The `ingetrazo` CLI used by package.sh now selects native Vulkan on Linux/Windows and native Metal on macOS. Production enables native World and CAD together; engineering examples keep their explicit options. There is no production OpenGL or wgpu selection. Existing Metal unsupported-stage CPU compatibility remains visible and full Metal pixel parity is still open.

Native-only viewport rendering no longer eagerly decodes/uploads scene images into egui or populates a CPU texture map. Paste uploads only its CPU-consumed images; ordinary CPU compatibility remains textured and shared UI handles are retained. The normal app also emits a title command only when its title changes, removing egui's unchanged-title repaint feedback loop. Focused actual viewport and first/unchanged/changed title tests pass.

The final actual CLI opened banca-pergola-yanque.igz without renderer opt-in flags on software Vulkan and the RTX 5090, displayed the original model, survived 800x600/1100x700 resizes and closed through WM_DELETE_WINDOW. Both runs retain screenshots, loaded-document title, binary SHA, one world geometry upload and zero final tracked GPU allocations. Root visually inspected the final RTX capture. This is startup/render/lifecycle evidence, not exact Python pixel parity or physical input acceptance. The matching NVIDIA driver bundle was mounted only into an owned read-only networkless container; no host driver installation changed.

In the same short software startup/resize scenario, CAD callback count fell from 426 before the title fix to 32 after it (RTX final 21). This supports removal of the forced repaint loop; it is not a general frame-rate/CPU-utilization benchmark. Its retained failure was resolved by using the inspected mount source; only that failed hardware launch was retried.
