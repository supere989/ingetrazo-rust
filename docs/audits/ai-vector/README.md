# Real VM vector primitive prerequisite

Ten actual PySide recipes execute unchanged in real RustPython, asserting exact construction/copy, setter values, float32 addition/subtraction/scalar multiplication/division, length and squared length, normalization and fuzzy thresholds, dot/cross, equality, unary negation, componentwise multiplication/division and in-place object identity. Two mutated literal assertions execute through the same native fixture and fail. The initial length failure is retained: Qt qHypot uses scaled float32 std::hypot3 arithmetic (libstdc++), not a double sqrt or unscaled squared length. Official Qt source URLs are recorded in provenance.

This is a partial genuine QVector3D payload, not full PySide compatibility or production scripting. Matrix projection/unprojection, distances, indexing, representation, all overload/type/error behavior and platform-library hypot differences remain required. VM object/compiler/native-memory bounds are not completed by scalar fuel ticks. Editable Mesh/Vertex/Face projection, existing-state mutation rollback and full Group API remain the next required dependencies. Production execution stays disabled. Existing tuple helper geometry is deliberately unchanged until the editable adapter consumes real vector objects.

In-place arithmetic computes a stack array and mutates the original payload; it does not allocate a temporary vector object. Existing vector mutations still need transaction observation before production activation.
