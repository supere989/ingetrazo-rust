# Private controller reset/discard boundary

This standalone controller owns its VM, persistent scope and private document owner. Callers receive no VM, reset or native-module registration API. Each script stages one typed transaction. Ordinary Python failure, budget poison and preparation refusal discard the transaction before the host resets fuel. Success consumes the transaction into one command before reset; a no-op adds no history. Poison explicitly refuses commit even if a future session implementation returns success.

Seven actual executions pass: append, no-op, partial Python failure, caught BaseException exhaustion, following-session execution with retained globals, real configured index admission refusal, and retry after lifting that quota. The native callback unwind test uses a real Rust panic after staging an edge. An immediate RAII guard removes and drops staging; mesh/history remain unchanged. That controller is permanently tainted and refuses reuse, while a new controller on the same thread can run. Catching an unwind does not prove that the interrupted VM is reusable. The panic hook exists only in test compilation.

Raw Python exceptions are retained without invoking script-defined formatting; preparation failures retain their reason separately. Boolean fixture status is not the run_python traceback protocol. Traceback rendering, exception finalization after reset, persistent scope rollback and host/VM destruction deadlines remain unproved. Globals intentionally survive ordinary script failure; only the append transaction is atomic here.

The checker invokes the same validator on four mutated records: early reset, partial publication, lost poison and incomplete inventory. It tests evidence protocol rejection, not a substitute runtime timeout. The actual callback unwind control covers the missing-guard failure identified during review. Initial development compilation failures (delimiter and module-local imports) were corrected before the retained executable.

No production bridge dependency or script admission is enabled. No wall-time claim follows from bytecode fuel. Compiler/native builtins, fallible allocation admission, staging/history memory budgets, all scene operations/imports and full original script compatibility remain required. Owner new/replace/undo/redo still have infallible pre-mutation allocations. Index-entry refusal is a real quota, not comprehensive OOM handling. Existing unchanged source/owner evidence was reused; no broad suite ran.
