# Live chain and baseline previews

The unchanged original application produced five cohorts with 106 observations: fresh and selected-seed chains and baselines, plus Escape, tool, sheet and Undo/Redo boundaries. Each observation records actual pointer actions, composition, selection, shown owner, history, run state and the retained preview path. The original preview item paints the isolated page image at two pixels per millimetre; separate viewport grabs preserve application evidence. The observer asserts unchanged document, history, selection, pending state and local version.

The first attempt stopped because its assertion expected a Shift-only event to change a chain axis. The original `_shift_changed` calls `_ortho_anchor`, which excludes chain points. That failed attempt is retained. The completed capture preserves inert key-only phases and uses actual Shift-bearing mouse events for horizontal and vertical axis changes. No original code was edited. A prospective total is absent; the ordinary dimension is authored only when the chain finishes.

The native consumer uses the existing `composer_specialized_workflows SOURCE NATIVE --run-previews` binary mode. It drives actual App input and toolbar controls, then captures submitted production CAD callbacks from the actual frame output. Its isolated image composites those immutable CPU coverage spans. This proves prepared preview primitives when the strict checker passes; it does not prove a GPU framebuffer or full window pixels. Native acceptance is pending the shared build and replay.

Run the original saved-file reader with `reference-composer-run-preview-reopens.py SOURCE NATIVE`, then `check-composer-run-previews.py SOURCE NATIVE COMPARISON`. The checker requires the complete ordered inventory, literal state/path/style/pose values, exact decoded primitive pixels, five original saved-file readers, actual paint submission and typed reuse/read-only controls. It preserves independent state and pixel diagnostics on failure. Existing 220 run observations are reused separately rather than recaptured.

`source-records.zip` contains the original inputs, saved files, observation JSON, primitive images and viewport grabs, plus the initial failed observations and both capture logs. Session, configuration, cache and partial duplicate files are excluded. The manifest binds all member bytes and the producer, contract, checker and reader revisions.
