# Independent consumer failure collection

The existing integrated runner now records explicit producer dependencies with a small reusable sequential stage collector. Binary hashes and authenticated archives are prerequisites, not output-file-existence guesses. Failure or timeout skips only dependent consumers/readers/checkers; unrelated stages continue. Existing stdout/stderr paths, subprocess timeout and successful result schema remain unchanged, with the new Import result added. `stages.json` records pass/fail/skip and errors; `result.json` is nonzero/fail whenever any stage fails or skips. Earlier result/stages files are retired at startup, and summary reads run only after all prerequisites succeed, preventing reuse of stale native JSON or a previous pass.

Archive authentication gates its producer(s). Axes/Documents/Paste/Box/Edit/Text/Finite-mesh use native→reader→checker chains. Fillet nested and volume checks independently depend on its native producer. Delete, anchors, preview and Units strict checks and original readers independently depend on native. Material native and tray producers are independent; their combined reader needs both, then its checker needs both plus the reader. Cursor retained-negative rejection is independent of the current native producer. Other workflows use native→checker. Shared binaries gate only their consuming modes. The existing context_document_lifecycle binary also runs --import-preferences against seven authenticated retained inputs, with no new executable/source capture.

Syntax compilation passes. `python3 scripts/check-consumer-stages.py` runs only small Python child processes: exit7 producer, skipped reader/checker despite an old native JSON file, continuing independent producer/checker, a real .05s timeout, failed archive and skipped producer. It proves terminal failure/nonzero, no old pass reuse/no success-summary call, and separately verifies unchanged successful summary fields. Full real roster replay belongs to root integration. No Rust builds/tests or source captures were performed for this change.

The runner was based on current authoritative integration's 22-binary script, rather than the owner's earlier 17-binary version; root should use the reviewed final file when integrating to preserve all accepted roster additions.
