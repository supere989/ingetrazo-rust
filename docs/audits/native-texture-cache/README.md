# Cold texture cache and actual source decoder controls

`reference-source-texture-decode.py` invokes the pinned original Viewport._get_texture under an actual Qt OpenGL context, without replacing the texture object or alpha computation. Six literal PNG files retain source RGBA bytes, Repeat/min/mag sampler settings and hard-cutout decisions, including alpha128/129 and adjacent coverage2457/2458 outof4096. Production cold decoder matches all six byte streams and flags. Two mutation negatives are rejected. This is an actual Mesa source context, not NVIDIA pixel rendering proof.

`native_vulkan_texture_cache_probe` uses production optimal-image resources and real Vulkan descriptors on llvmpipe: borrowed immutable encoded identity, candidate image rollback before publication, descriptor preparation before publish, actual GPU readback, hit with no additional hash/decode/upload, distinct identity real allocation denial preserving prior view, signaled-fence/serial retirement and zero final ledger. Its empty submission exercises ownership admission, not actual sampled draw consumption; direct texture shader/draw acceptance follows separately. Default probe requests strict NVIDIA discrete hardware.

BLAKE3 computes an immutable encoded content identity only on cold admission; no extra encoded byte copy is made. PNG/JPEG support is bounded: original Qt additional formats, high-bit-depth/profile/orientation controls, cache budgets/streaming and native Metal remain open. Failed prepared candidates cannot replace published images; caller retires referencing descriptors on the same actual completed draw fence before eviction. The production cache does not enable diagnostic TRANSFER_SRC; only the explicit evidence constructor does. Existing wait-failure unbounded device-idle cleanup remains an open lifecycle limitation.

Build examples native_vulkan_texture_cache_probe and native_texture_decode_protocol, generate source fixture with the parity Python interpreter, run protocol INPUT OUTPUT, then check-source-texture-decode.py INPUT OUTPUT. No Qt/process wrapper is in the production runtime.
