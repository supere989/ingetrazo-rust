# Opt-in Intel reflected-sample diagnostic

This draft keeps production source-sample admission unchanged. It admits the experiment only when fixed native four-sample positions are exactly the index-preserving Y reflection of the measured reference pattern. It reflects final clip coordinates and front-facing conventions, folds output row reflection into the existing ordered GPU compute resolve, and reflects diagnostic/depth-query rows without changing source inverse transforms. It uses native Metal raster and compute, with no CPU renderer or backend wrapper.

Root-only build: `cargo build --locked -p ingetrazo-gui --example native_metal_section_resolve -j2`. Actual Intel Mac diagnostic: `target/debug/examples/native_metal_section_resolve OUTPUT --reflected-diagnostic`. Strict comparison: `python3 scripts/check-metal-reflected-samples.py OUTPUT --output COMPARISON.json`. The dispatch-only workflow runs those commands once and retains failure artifacts. No command has been executed for this draft.

The ten section images and closed sample observations are actual unchanged original Mesa/Xvfb artifacts, while the depth-selector witness is NVIDIA RTX 5090 evidence. The three-point iso archive additionally preserves original per-sample depth bits. These are separate provenance scopes: the retained Intel CGL observation failed accelerated pixel-format creation, so it supplies no valid Apple source selector oracle. Source bindings authenticate the existing bytes; nothing is recaptured.

The consumer reports complete candidate/reference RGBA, per-sample RGBA and depth bit patterns at the retained closed/iso coordinates, native transport/resource observations, three warm frames, fill/cuts routing, pinned-target budget refusal with held-frame preservation and foreign-context/mode refusals. The checker compares the frozen images and raw sample/depth bits strictly, retaining discrepancies and simulated row/sample/depth corruption rejection controls. Existing float-normalization/iso depth residuals remain failures, not tolerances or accepted normalization.

Production document annotations, valid Apple CGL selected-depth semantics, full text/UV/overlay orientation and packaged startup remain separate acceptance gates. Eligibility mathematics and successful diagnostic execution alone cannot release production admission. Root owns all compilation, native execution and publication.
