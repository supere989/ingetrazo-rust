# Exact BC7 texture admission through the native Vulkan cache

Source commit `1b7da4e1` adds a real compressed upload consumer, with unchanged AssetId ownership and warm-frame preparation. Linux/Windows logical devices enable supported BC compression. Cold hard-cutout PNG images may use BC7 after actual format/extent/usage checks and exact per-block decoded-texel validation; unsupported, inexact, nonsaving and mipped images retain RGBA. Existing source row mirroring and no-mip cutout behavior are preserved. The bounded mode5 encoder follows the [Khronos BPTC specification](https://raw.githubusercontent.com/KhronosGroup/DataFormat/main/bptc.txt); it tries four channel rotations and component bounds, never fitted error or a tolerance.

The existing direct Vulkan resource owner now uploads real block rows into BC7 optimal images through its retained <=8MiB staging allocation and transfer command/fence. Image admission, allocation budgets, transaction publication and uncertain-completion quarantine remain owned by the existing path. Production texture descriptors and shader sampling are unchanged. Counters expose actual uploaded bytes, accepted compressed images, logical savings and cold compression work. No subprocess or image backend was added.

## Actual acceptance

Both software Vulkan and strict NVIDIA RTX5090 pass: nine cache inputs with BC enabled and disabled (four channel rotations, odd edges,512x512 mask,inexact fallback,opaque/mipped fallback,tiny nonsaving fallback); every decoded texel matches source RGBA after the original row orientation. Diagnostic compressed decoding is performed by Vulkan GPU blit to RGBA, not the encoder's CPU decoder. A changed packed endpoint fails the same hardware comparison. Eighteen actual allocation denials preserve the existing images/ledger. Each image survives100 warm cache admissions without decode,encode or upload. A direct4097x2049 BC7 image transfers8,413,200bytes in two chunks; raw block readback and all8,394,753 hardware-decoded texels are exact across chunk and partial-block boundaries. Staging stays<=8MiB.

Four complete256x256 production World frames compare RGBA vs BC7 exactly, including a shared face/reference-plane image, camera motion/zoom, reference removal and XRay. One image upload serves both owners; warm draws reuse it. All resource ledgers return to zero. On RTX5090 the512x512 mask's actual GPU image allocation and upload each drop1,048,576→262,144bytes. This is a measured75% reduction for that input, not a universal VRAM reduction. Cold timing is from an unoptimized development build and includes the failed replacement retry; no optimized throughput or total-frame performance claim. Final NVIDIA transport completes in1.75seconds.

Three focused portable encoder tests cover anchors, rotations, invalid dimensions, partial blocks and late inexact fallback. Original no-NVIDIA container refusal and earlier successful captures are retained separately. The final proof uses a disposable read-only NVIDIA devbox and strict adapter matching, with the binary hash and command retained; no software substitution. `manifest.json` verifies every compressed archive entry; `provenance.json` pins runtime source and binary. Reproduce with `cargo run -p ingetrazo-gui --example native_vulkan_exact_bc7 -- OUTPUT_DIR` inside a NVIDIA devbox, or add `--software-fixture` for the separately labeled CPU fixture.

## Still open

General/photo BC encoding, additional exact modes, normal-map formats, compressed authored mip chains, mip streaming, persistent parallel encoding workers, native Metal compressed texture consumers and supported ray-tracing acceleration structures remain required. This bounded optimization proves equality with the existing native RGBA consumer; it does not close original-Python full-render parity or any complete release gate.

Independent artifact replay (`scripts/check-exact-bc7.py`) verifies all117 archive entries,262,144 rendered pixels per backend, and rejects pixel/allocation/fallback/ledger mutations. `independent-check.json` retains that result. A separate read-only reviewer found no encoding, block-transfer, lifetime or capability issue, and identified public mutable image-format metadata as an API hazard; the follow-up makes this new field private. The retained GPU binary is the pinned runtime commit above; visibility-only hardening is covered by combined compilation without repeating its GPU workload.
