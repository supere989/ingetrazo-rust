# Move live-preview contract and proof boundary

Source mapping: original `tools/move.py` `_apply_preview`/`_revert_preview` maintain the displacement from the grab; `on_key` toggles Ctrl and restores originals before copy wireframe preview; `rubber_band_lines` supplies grab vector and translated selected geometry; `_commit` reverts preview before one History command. The runnable `probe-python-move-copy.py` exercises those operative methods with controlled selection/world points. It is controller evidence, not pixel/timer evidence.

Rust captures original positions and group/section-plane transforms only for selected targets at grab. Preview applies absolute deltas, retains vertex identities and attributes, and allocates no Scene snapshot per frame. The existing undo snapshot allocation is reconstructed to grab-time geometry and version. Actual commits restore preview first, maintain the spatial index, and record one undo entry. Ctrl, Escape and changing tools restore the exact selected geometry. Invalid VCB/click input retains the current visible preview without creating history. Real preview changes notify the shared application model revision; unchanged pointer frames do not.

Copy preview is translated wireframe, including nested group world placement, not committed duplicate topology. Count/spacing arrays are separately retained copy-command retyping transactions. The existing native ash Vulkan/XTEST short Move, center reacquisition and deletion gesture passed in an isolated llvmpipe/Xvfb run (`center-tracking-native-curve-move-live-preview`); dedicated rendered copy and independent live-preview acceptance remain pending.

## Intentional active-history correction

The retained original `probe-python-move-history-boundary.py` executes the actual original MainWindow Undo during an active Move over a newly authored edge. Undo removes the edge, but Move retains its anchor and two captured targets. This is normative source evidence of a stale-target boundary, not a passing literal-parity case. Rust retires and restores the transient Move before Undo/Redo can replace target entities. Existing committed history is then undone/redone normally, and redo geometry excludes transient deformation. This narrow correction prevents detached/stale target use; composer history guards remain before the hook.

Original groups-only drags use frozen scratch rendering without scene-version churn. Rust currently changes selected group placement matrices without cloning geometry, but not the original frozen scratch strategy. Large group-drag renderer/pack performance, tool-specific labels/dimensions/images and broader gesture coverage remain open. These bounded controls do not verify all P08 parity.

## Intentional array boundary cleanup correction

Original `_make_copy_builder` authors faces through `AddFaceCommand(auto=False)`. `AddFaceCommand.undo` calls `Mesh.remove_face`, whose explicit contract detaches radial face incidence while retaining its boundary edges. The copy builder does not separately own every new face boundary with inverse edge commands. Re-laying arrays therefore leaves abandoned wires; ordinary square-only source control already records edges 16→24→24 for 3x→/3→2x while native complete arrays are 16→16→12. Original Undo restores the original face count but retains 24 edges versus the initial 4. The corrected owner probe labels face-count restoration only and retains the literal topology mismatch, rather than calling it complete document restoration.

Rust re-lays against the preserved pre-copy mesh and restores that original mesh on Undo, preserving unrelated geometry, vertex identity and original attributes. This is an explicit integrity correction for orphan copy boundaries, not literal parity for that source case. Independent mixed-holed reference controls and full selection/cache/redo proof are required before broad acceptance; parent/validator retain those source outputs independently.
