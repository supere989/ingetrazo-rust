# Retained embedded-font text baseline failure

Experimental example paper_text_pdf_fixture.rs, direct process-local pdf-writer + native PaperFont shaping; no application export change. Nine selected single-line LTR font runs use actual source text/font file metadata and native positions derived from font shaping. Actual original paint_text_mm helper PDFs from paper-text-native-contours/original are authoritative. Fixed source helper A4/300dpi physical frame and font14pt recipe are explicit fixture constants; this does not prove general layout.

Strict QtPdf/PDFium complete-page RGBA comparison at72dpi FAILS every case: accents612, bold443, combining137, italic525, kerns239, latin480, mono503, serif499, serif_bold185 pixels. These first actual source/native PNGs and native PDFs are retained. Source fullfont glyph positions pass independently; this page failure is not waived. Native embeds original complete TrueType font while Qt emits rebuilt no-instruction glyph subsets, so embedding strategy needs source-compatible investigation. This observation does not prove subset difference is the sole raster cause. No original embedded font program is redistributed. Text PDF/UI remains OPEN.

Source qfontsubset.cpp (primary reference https://raw.githubusercontent.com/qt/qtbase/v6.11.0/src/gui/text/qfontsubset.cpp) rebuilds glyphs from getUnscaledGlyph paths, re-encodes2048em glyph tables; Qt source FT getUnscaledGlyph uses unscaled glyph path extraction. Exact intermediate outlines/table controls and original wholepage reruns are required before implementation promotion.
