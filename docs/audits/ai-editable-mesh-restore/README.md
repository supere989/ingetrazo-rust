# Source-compatible root field failure restoration

The same original three append states now match all replacement identities, and a fourth operative source state additionally mutates existing attrs with an integer-tuple key/arbitrary shared values, reverses the Face.loop, changes a position wrapper and clears both root membership lists before raising. Rust restores the root lists in place, keeps real Vertex/Face objects, replaces Face loop/hole lists and attribute dictionaries with prepared shallow copies, and replaces position wrappers with copied original values. Shared nested mutable values retain their identity and their in-error mutation, matching the original's shallow rollback limitation. There is no JSON object boundary.

Preparation reserves logical reference-record/loop charges before script execution and completes replacements before any restoration writes. A pre-execution logical budget refusal prevents the script from running, preserves current state and resets the session only after staged work has been discarded. A prepared restoration guard handles the tested Rust unwind; the controller remains tainted and refuses reuse, while a new controller can run on the same thread. This does not establish safe reuse of a VM after arbitrary native panic. Cycle teardown still reaches zero native charges.

The strict checker compares all fields/types of four complete ordered geometry/identity states, invokes its same validator for nine mutations, and rejects the literal previous three-state native result specifically through the same recursive state comparator. The old full-identity failure remains retained in ai-editable-mesh. Only this operation family is accepted; full scripting remains disabled.

Important limits: preparation currently copies O(root VM reference graph) shallow baselines per execution. It does not clone native Mesh/Scene geometry, but is not the required final O(1) transaction-begin path. Mutation-observed persistent baselines are required before production. Logical charges exclude VM object/dictionary storage, compiler/native builtin memory and allocator overhead; they are not an allocator-enforced memory cap. Success-path projection of existing vertex/loop/attribute changes and controller Undo/Redo are not implemented. Edge/radial fields, setters/constructors, Group/Scene integration, external handle teardown and the full original API remain required. Hostile destructor/native callback reentry during restoration has not been proven; an explicit host-abort/poison boundary before releasing replacement payloads needs audit. Whole-document rollback cannot be claimed from these source shallow-reference controls.
