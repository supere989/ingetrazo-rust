# Genuine editable Mesh routing prerequisite

The standalone real RustPython module now routes Mesh.add_face into a persistent FaceOwner/source registry. Actual Vertex and Face objects back persistent Mesh.vertices/faces lists; Face.loop and hole_loops contain stable real vertices, attrs remain arbitrary VM objects, and Face.vertices is a fresh list of the same position wrappers. Face.normal/centroid read the real current loop. New vertex positions copy the input vector, matching original Vertex construction. Native append projection uses prepared welded IDs and geometry; no per-operation base Mesh/Scene clone or JSON attribute boundary.

Root/managed meshes stage append mutations per actual Mesh identity. All touched owners prepare before any publishes. Actual budget pressure after the first prepared owner refuses the second; both old native meshes and persistent list memberships remain unchanged, and detached returned Face/Vertex handles remain readable. Private scope-only Mesh objects publish their own edit immediately and retain it through a later script error, matching the source ownership distinction. Host adoption in this fixture is engineering-only; it is not live Scene/Group integration. Controller teardown clears its scope under VM poison and collects a deliberate Mesh→Face.attrs→Mesh cycle; native charges return to zero.

The actual original executor produces three full ordered append/shared-vertex/failed-append geometry states. The prerequisite checker verifies complete geometry and the stated list/Face identities; seven mutations invoke the same validator and reject. This does **not** pass full original object semantics: on root failure, source SnapshotImport replaces existing Face.loop, Face.attrs dictionaries and Vertex.position wrappers. The staged adapter keeps these wrappers. All three differences are explicitly observed and retained; `--full` rejects the current candidate. No tolerance or normalization hides them.

Remaining required work includes those replacement semantics, arbitrary existing object/vector/list/attrs edits and failure restoration, full Edge/radial/set graph, constructors/properties/methods, controller Undo/Redo, real Group/Scene adoption and persistence, external handles after controller teardown, VM/native/physical memory bounds and all original helpers/imports. Current private FaceOwner retains proof history that needs a direct live-geometry ownership path; logical shared charges exclude VM objects and arbitrary dictionaries, compilation and allocator overhead. Mutable membership lists can currently diverge from native topology: production is disabled until observation/admission and full journal projection are implemented. This is no rendering/application/run_python acceptance claim.
