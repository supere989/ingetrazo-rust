- **Verified**: original/Rust semantic comparison and user workflow evidence satisfy the row's acceptance criteria.

- **Partial**: incomplete implementation, disconnected UI, placeholder behavior or known preservation gap.

## Maintenance protocol

This is the canonical current tracker. Keep feature IDs and acceptance criteria stable. Update the checkpoint and relevant row; place detailed commands, source hashes, failures and results in one coherent batch under `docs/audits/`. Historical checkpoints are retained in [PARITY_PROGRESS_HISTORY.md](PARITY_PROGRESS_HISTORY.md); do not append old run summaries here. No full row becomes Verified until its complete criterion is demonstrated.

Build cadence: each owner reuses one target directory; component consumers build together once and execute authenticated named binaries directly; independent work uses isolated worktrees. Cross-worktree target handoffs invalidate changed local-path package artifacts while retaining external dependencies. `scripts/check-rust-workspace.sh` runs all test targets/doctests and checks examples without unnecessary diagnostic linking; named acceptance examples still build and execute. CI caches dependencies with a pinned action and omits debug/incremental data. Run local focused checks and jointly built application consumers. Published CI owns the one broad workspace suite per stable integration batch; run it locally only if CI is unavailable or a failure requires local diagnosis. Repeat completed checks only for changed code, a failure, or an unresolved concern. Poll CI at integration boundaries. CI finishes active push runs and saves their caches while retaining only the latest queued push; PR updates cancel superseded checks. Documentation/evidence-only pushes skip the broad acceptance workflow; pull-request checks keep their existing behavior. Retain failures and canonical evidence, then purge terminal temporary copies. An agent owns implementation through its consumer and required validation, rather than ending at an API prerequisite.

`python3 scripts/audit-parity.py` remains the bounded document audit entry inside devbox. It returns failure for build/conversion errors, not an overall parity verdict. Progress is measured by demonstrated acceptance criteria, not test counts or source-line counts.
