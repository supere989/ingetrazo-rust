Build cadence: each owner reuses one target directory; component consumers build together once and execute authenticated named binaries directly; independent work uses isolated worktrees. Cross-worktree target handoffs invalidate changed local-path package artifacts while retaining external dependencies. `scripts/check-rust-workspace.sh` runs all test targets/doctests and checks examples without unnecessary diagnostic linking; named acceptance examples still build and execute. CI caches dependencies with a pinned action and omits debug/incremental data. Run focused checks for changed behavior and one combined suite after an integration batch stabilizes. Repeat completed checks only for changed code, a failure, or an unresolved concern. Poll CI at integration boundaries. CI finishes active push runs and saves their caches while retaining only the latest queued push; PR updates cancel superseded checks. Tracker-only pushes skip the broad acceptance workflow. Retain failures and canonical evidence, then purge terminal temporary copies. An agent owns implementation through its consumer and required validation, rather than ending at an API prerequisite.

`python3 scripts/audit-parity.py` remains the bounded document audit entry inside devbox. It returns failure for build/conversion errors, not an overall parity verdict. Progress is measured by demonstrated acceptance criteria, not test counts or source-line counts.
