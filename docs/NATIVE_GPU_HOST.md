# Native GPU host checkpoint

The `native_vulkan` example runs the production `IngeTrazoApp::update_ui` directly in winit 0.30 and submits egui meshes with ash 0.38 / egui-ash-renderer 0.7.0. There is no wgpu dependency in this build. The normal launcher remains the transitional Glow host pending acceptance. Linux/Windows Vulkan is the target; macOS requires a separate native Metal implementation, not the upstream portability/MoltenVK route.

## Verified boundary

The shared update function preserves document/session logic and existing texture handles. Native root viewport close events enter the application Save/Discard/Cancel guard; returned Close/CancelClose commands determine exit. egui-winit supplies keyboard, pointer, IME and platform clipboard handling. Redraw scheduling follows egui repaint delay and input wakeups, with an event-loop proxy for immediate background repaint requests. A single in-flight fence retires texture frees safely. Zero extent postpones swapchain recreation.

`cargo test -p ingetrazo-gui --lib`: 73 passed, 1 ignored. `cargo tree -i wgpu`: no packages. Actual disposable Xvfb startup used Mesa llvmpipe Vulkan 1.4.318, with production menus, viewport and tray visible in retained capture. Extension diagnostics describe advertisement, not enabled hardware RT. Use `scripts/check-native-vulkan-startup.py target/debug/examples/native_vulkan OUTPUT` for native resize captures and an actual WM_DELETE_WINDOW clean-close control. Do not equate screenshot existence with pixel parity.

## Remaining production gates

The checkpoint still consumes the existing CPU projected egui scene painter. Full viewport acceptance requires cached world vertex/index/texture uploads and direct depth/stencil GPU rendering; the egui pass becomes the UI overlay. Existing historical wgpu screenshots must be rerun on the actual native backend.

Resource budget initialization can use exposed VulkanContext instance, physical_device, device, graphics_queue and command_pool. The default upstream allocator and synchronous texture uploader need replacement or preflight enforcement: bounded staging chunks, explicit heap budgets and committed accounting, texture deduplication, BC7/BC5 support checks, mip streaming and retained scene state when allocation fails. Presentation semaphores are allocated per swapchain image and recreated after idle; error propagation, device loss, screenshot readback, clipboard actions and native close tests remain open.

Shared backend APIs should expose adapter diagnostics, immutable resource revision/cache handles, budget admission, upload completion, draw/compute submission, present and readback. Native Metal implements these independently. Ray tracing requires actual feature/property queries, enabled acceleration-structure/ray-pipeline features, BLAS/TLAS caches and hardware benchmarks; extension names alone are insufficient.

Quadratic CPU work and other eligible pipelines require persistent worker processes as explicitly directed. Root owns scheduler/budget modules: immutable binary geometry/task buffers and shared outputs should cross that boundary without per-frame JSON/full Scene copies or worker startup. Worker counts and task grain require throughput/latency/memory measurements. GPU submission stays direct; optional integrations remain in parity scope when optimized.

This is a reviewable host proof, not full renderer or platform parity.

## Budget/resource stage

Backend-neutral `gpu_memory::MemoryBudget` reserves exact allocation bytes, commits only after API allocation/binding, and retains retired allocations until actual free after the relevant fence. `texture_mip_bytes` accounts RGBA8 and complete BC7/BC5 blocks, layers, depth, odd dimensions and mip chains with overflow checks. This arithmetic is not a compressed texture implementation.

`native_vulkan::budget::VulkanBudget` queries live VK_EXT_memory_budget properties when advertised, reports application accounting and imposes heap admission. Defaults use 80% of heap capacity and 90% of live driver budget; `INGETRAZO_GPU_HEAP_LIMIT_BYTES` explicitly overrides each application's heap limit. Driver usage is an estimate; already-accounted application allocations are not counted twice.

Pinned vendored egui-ash-renderer 0.7.0 exposes a default allocator observer so UI texture images, staging allocations and mesh buffers use actual Vk memory requirements and heap mapping. Admission/bind failures roll back, and safe actual frees release charges. Pending rejected texture deltas retry without destroying the document; successful deltas are removed individually. The synchronous uploader now uses bounded 8 MiB row chunks; asynchronous streaming, compression and upload responsiveness remain performance gates.

Pure queue selection preserves original indices, handles split graphics/present queues without requiring compute on graphics, and identifies a dedicated compute candidate. Actual suitable adapters rank discrete/integrated/virtual/other/software, with `INGETRAZO_VULKAN_DEVICE` index or unambiguous name override. Dedicated compute submission is not implemented merely by identifying it.

Actual `native_vulkan_budget_probe` admits a 256-byte image and forces staging admission denial, verifying zero committed/reserved leakage before continuing production UI; startup, two native resizes and clean close pass afterward. A 600000-byte admission limit causes an actual allocation rejection while the host stays alive and clean OS close remains functional. Full GUI library: 80 passed, one ignored. Independent nearest-sampler baseline is retained; the fork now routes TextureOptions to sampler state and partial updates preserve prior texels, independent corrected nearest/partial-update screenshots pass 16 samples and two negative controls (validator commits 5704164 and 48e1864).


## Direct opaque world stage

`INGETRAZO_VULKAN_WORLD=1` enables a bounded production viewport path: cached world-space opaque vertex/index buffers, Vulkan depth testing, and an offscreen sampled image submitted before the egui UI pass in the same command buffer. Camera motion changes the matrix without re-uploading geometry. Scene version, view version, monotonic application model revision and style invalidate the cache; the shared model revision must retain the composer ink-cache invalidation body when integrated. The ordinary launcher remains Glow and the opt-in path is not full viewport parity.

`native_vulkan::resources::Resources` admits actual buffer requirements, directly maps suitable unified device-local memory, otherwise transfers in at most 8 MiB staging chunks. Retired buffers remain charged until an actual signaled fence and matching completed draw serial permit destruction. The native resource probe uploads and verifies all 17 MiB, uses three chunks with 8 MiB peak staging, rejects collection behind an unsignaled Vulkan fence, then frees after actual queue submission and fence completion. This evidence uses llvmpipe unified memory; discrete GPU readback/performance is unproved.

The crossing-face fixture uses the production app and viewport: GPU fragment depth correctly leaves red on the left and blue on the right, whereas the retained centroid painter control paints both blue. `scripts/check-native-vulkan-depth.py` checks the positive image, retained failure and swapped-side negative control. Startup, two native resizes and clean OS close also pass; the unchanged geometry reports one upload across resizes. GUI library tests: 81 passed, one ignored; render library: 18 passed.

Depth/stencil storage is allocated, but stencil section masks are not yet implemented in this path. Textures, transparent geometry, edges, grids, annotations, native section fill, prototype GPU instancing, worker-assisted tessellation and hardware throughput/VRAM profiling remain open. The surface builder avoids CPU projection/HLR but still triangulates synchronously on cache misses. UI image staging remains synchronous with bounded 8 MiB chunks. GLSL and checked-in SPIR-V are reproducible with `scripts/compile-native-world-shaders.py` using shaderc 0.8.3; shaderc is a development tool, not a runtime dependency. Native Metal remains a separate implementation and hardware acceptance requirement.


## Bounded UI texture transfer

The vendored uploader now reuses a staging allocation capped at 8 MiB, borrows contiguous source row slices, and waits for a dedicated transfer fence rather than queue_wait_idle. An actual 4096×3072 RGBA image (48 MiB) uploads with only 8 MiB staging headroom, then accepts a partial lower-right update. Native screenshot samples are exactly red/green/blue/yellow across chunk boundaries and the partial region. The prior full-image uploader is compiled as a retained negative control and fails the same budget. Actual allocation rollback and native startup/two resizes/clean close are rerun. This is synchronous chunked transfer, not asynchronous mip streaming or compressed texture support; worker-assisted decode and upload responsiveness remain gates.


## Native section fragment clipping checkpoint

The world pass now clips model fragments using the original first-active world-plane convention (`views/viewport.py` around 1380 and `resources/shaders/basic.vert`): keep dot(normal, position - origin) <= 0. A 96-byte push-constant range carries camera, plane and enable state; changing the cut does not require clipping/re-uploading geometry. Actual active/reversed/inactive/disabled controls pass native screenshot samples, with the crossing-face depth fixture still passing after the shader change. Each control also passes startup, two native resizes and clean OS close.

This is fragment clipping only. Native section stencil fill, contour edges, overlays and quantitative comparison with the original OpenGL cut screenshots remain open. Fragment discard currently implements the plane boundary without enabling optional shaderClipDistance; future early clipping optimization requires queried features and preserved pixels. The old compositor is the default until the direct world path meets broader acceptance.


## Native stencil fill checkpoint

The world render pass now redraws clipped opaque back faces with color/depth writes disabled and stencil Replace(1) on passing depth, then draws the section quad with stencil Equal(1), clipping disabled and depth bias (2,2). This follows `Viewport._draw_section_fill` rather than constructing physical caps. The derived interior partition faces remain in the draw: a shared slab suppresses the top cap exactly as the original does. Transparent faces do not enter the opaque mask; coplanar back-face caps fail biased depth correctly. Cap buffers retire behind their last draw fence, and frame bounds are recomputed only when the cap/model/style key changes.

The backend queries common framebuffer color/depth/stencil sample counts and selects the original default 4× MSAA where supported, with explicit 2×/1× fallback diagnostics. Multisampled color/depth/stencil images and the resolved sampled image all reserve actual requirements through the same budget. Unsupported format-specific creation can still produce a visible allocation error; native Metal implements this separately.

Actual production World screenshots at 800×600 pass all ten retained original stencil controls using the established exact-zero/5%-positive gate. Top closed/reversed/duplicate are 20736 native vs 20164 original (2.84%); iso closed/reversed 10093 vs 9925, shared 8497 vs 8519. Shared top, transparent, coplanar and front are exactly zero. A retained actual wrong-winding draw gives zero for the closed positive control and is rejected. Independent actual original ablation disables `_draw_section_cut_edges` and gives 20736, exactly the native top count. Missing postfill contours explain the discrepancy; implementing the source contour pass remains required. Textures/alpha cutout, broader views and hardware proof also remain open. The fixture calls production World submission through the native host, while its full-viewport UI deliberately isolates rendering from document gestures. Every control also passes native startup, two resizes and clean close. GUI tests: 82 passed, one ignored.


## True headless GPU/readback checkpoint

`native_vulkan_headless_probe` creates the shared production VulkanContext without WSI extensions, surface, present queue, swapchain, window or display. Default device request is NVIDIA vendor 0x10de and DISCRETE_GPU; an explicit device-name filter may narrow it. It never substitutes software. `--software-fixture` explicitly selects llvmpipe for bounded software checks. `--vendor 0x1002` provides a strict wrong-vendor control on an NVIDIA-only device surface.

Production Resources adds bounded actual buffer/image GPU→host copies, host-read barriers and noncoherent invalidation, rather than mapping device-local allocations. The 17 MiB source uploads through three ≤8 MiB chunks and copies back every byte. Production World uses the same target owner, shaders, depth/stencil passes and geometry cache for offscreen rendering; two crossing-face renders verify depth and changed-geometry invalidation through GPU image readback. The flipped face legitimately changes shade, so the second frame checks red dominance rather than unchanged brightness. No second renderer is introduced.

The backend-neutral budget has a total 128 MiB admission cap for this probe across heaps, including reservations and retired allocations, and reports peak admitted/committed actual VkDeviceMemory requirements. Driver-managed pipeline/descriptor overhead remains outside explicit allocations and must be measured separately. The llvmpipe run peaks at 26214400 charged bytes, frees all explicit allocations, and passes unsignaled-fence retirement/refused collection followed by actual signaled release. Each diagnostic fence waits at most five seconds; `--timeout-control` actually waits on an unsignaled fence and exits124 near five seconds without destroying potentially pending resources. This fail-fast process policy is restricted to explicitly diagnostic contexts; the interactive host keeps its current session/error behavior.

Commands: `target/debug/examples/native_vulkan_headless_probe --output /tmp/depth.png` for strict NVIDIA hardware, or `--software-fixture` for software evidence. Existing display-dependent lifecycle still passes after the offscreen/readback refactor. Hardware execution, independent device provenance, cut contours, compressed/mip textures, RT activation/benchmarks and native Metal hardware remain acceptance gates.


## Direct GPU postfill contour checkpoint

Original `views/viewport.py::_section_cut_segments` emits a segment only when a world triangle has exactly two strictly crossing edges. `_draw_section_cut_edges` draws its unclipped quad after fill, including visible transparent faces: camera-eye distance, FOV and logical viewport height set the width; the plane normal supplies the 0.6-width lift. The Vulkan vertex shader now assembles these same quads directly from readonly storage views of the cached world vertex/index buffers. Opaque geometry is reused, with separate cached transparent contour buffers. No CPU projection, additional scene serialization or compute queue is introduced. Storage limits are checked and transfers explicitly synchronize vertex-stage storage reads. The pass writes ordinary LEqual depth, without stencil or polygon bias, and remains active independently of ordinary edge display.

Fresh actual native software screenshots pass the unchanged ten-case exact-zero/5%-positive gate: closed/reversed/duplicate Top 20235 vs original 20164 (0.35%); closed/reversed Iso 9927 vs 9925; shared Iso 8391 vs 8519 (1.50%). Every zero control remains zero. All ten native startup/resize/close sequences pass; the wrong-winding retained negative remains rejected. The earlier contour-disabled 20736 Top capture and original runtime ablation are retained. Residual raster boundary differences remain visible, not relabeled exact pixel parity. The fresh production headless 17 MiB copy/readback and depth/cache/invalidation proof also passes after this stage.

Independent RTX5090 acceptance of the preceding headless 0b44d7d source is recorded separately by validation commits 1367e6b/15e76d7: actual discrete GPU readback, directmapped0, bounded staging, strict selection refusal, fence timeout and ledger cleanup. That proof does not promote the new contour pass, hardware WSI, compressed textures, RT or native Metal. Contour correctness for larger hole/triangle corpora, storage-range chunking, prototype reuse and GPU throughput benchmarks remain open. Native Metal still requires its own implementation and actual Mac hardware acceptance.


## Bounded contour storage and transactional replacement

Ordinary opaque models keep readonly views of the existing world buffers with zero additional contour position bytes. Oversized buffers now fall back to cached XYZ-only triangle chunks, each bounded by min(maxStorageBufferRange, 8 MiB), with implicit indices. Transparent contour buffers always use the compact layout: three floats per triangle vertex replace the unused 48-byte position/normal/color/UV vertices and separate indices (36 vs 156 logical bytes per emitted triangle). Descriptor pools are prepared transactionally and replaced only after the actual draw fence completes. Partial quota failure retires prepared chunks while retaining the old descriptors, geometry, cap and plane/camera/color uniforms. Geometry cache identity now excludes contour edge/fill colors; uniform-only changes reuse buffers. Document revision changes remain conservative and may rebuild unchanged geometry after section-only app history changes.

Actual forced 36-byte GPU ranges pass complete image equality against normal ranges for fourteen independently captured original IGZ inputs (15ee39a): closed, shared/reversed slab, duplicate, transparent, coplanar, front/Iso, hollow and shared hollow-seam. This equality preserves existing original mask residuals rather than claiming exact original raster parity. The dedicated 72-byte hollow probe prepares sixteen chunks/1152 extra logical position bytes, exercises a real quota denial after five partial chunks, proves unchanged previous full GPU image despite a changed attempted cut plane, and frees all explicit allocations. Camera/edge color/plane updates remain cached; opacity moves the mesh into transparent contour buffers and causes one rebuild.

The small software fixture records cold build about 0.316 ms, compact position preprocessing about 0.003 ms, and 100 warm cached calls averaging 0.000650 ms. These are CPU wall times for this bounded fixture, not GPU throughput claims. A reusable diagnostic timestamp query pool also reports full World GPU command duration with the selected queue timestamp precision. Software timestamps, first-use shader compilation and forced one-triangle draw overhead remain explicitly unsuitable for hardware throughput extrapolation. The production app does not allocate timestamp pools per frame. Logs and input/output hashes are retained under docs/audits/native-vulkan-contour-chunks.

Command: `native_vulkan_contour_chunks_probe --software-fixture --corpus-root DIR --output DIR` expects the independently frozen original/hollow-original IGZ folders; without --corpus-root it runs quota/cache/opacity controls. Omit --software-fixture to require NVIDIA discrete hardware. `INGETRAZO_SECTION_STORAGE_LIMIT=36` lowers only the engineering GUI section fixture storage range, never hardware limits. Remaining cold copies are scene triangulation into the shared CPU surface buffer and linear extraction of compact XYZ chunks; no repeated warm extraction occurs. Persistent worker preprocessing, shared prototypes, memory suballocation, real large-model GPU throughput, textures/alpha and native Metal hardware remain gates.


The diagnostic probe also accepts `--perf-triangles N` (bounded 1..250000), `--storage-limit BYTES` and `--transparent`. It constructs a linear synthetic triangle fixture without edge editing topology, runs eleven actual GPU draws, excludes the first timing as warmup, reports ten selected-queue timestamp intervals and verifies zero warm geometry uploads/allocations plus final ledger zero. Readback runs after each timestamp interval and is explicitly excluded from reported draw duration. The committed software 10k/100k/transparent-10k JSONs are fixture measurements only; at this checkpoint transparent timings measure contours, since transparent face drawing is the next stage. Hardware throughput and representative CAD corpora remain unproved.
