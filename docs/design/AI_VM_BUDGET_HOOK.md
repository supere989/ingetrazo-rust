# RustPython host budget: proposed hook surfaces (not implemented)

Pinned rustpython-vm0.6.0 public signal/trace APIs do not provide a non-script-disableable execution budget. sys.settrace may be disabled; script exceptions/signals can be caught. VirtualMachine.check_signals is only called when the eval breaker trips (frame.rs approximately3696). No vendored fork has been introduced.

A candidate minimal fork would add private host-owned budget/poison state to VirtualMachine (vm/mod.rs), and host-only arm/disarm APIs. ExecutingFrame bytecode dispatch must check it before decoding/executing each opcode, outside script exception dispatch: exhausted/poisoned frames return immediately without executing Python catch/finally code. Poison persists across nested frame returns, so caller exception handlers cannot resume execution. The host alone clears it after the staged journal is discarded. A genuine catch-everything loop and attempted sys.settrace(None) must be tested, plus nested recursion/generators and successful next session. Existing trace/error formatting is not silently normalized.

Fuel alone bounds bytecode count, not wall time. Instant deadline checks can be batched with a bounded opcode interval, but native builtins, compilation, integer arithmetic, sorting and allocations can run outside that interval. Every exposed CAD callback requires bounded inputs and the same host cancellation checks. JIT/threading would need corresponding hooks (current standalone dependency enables neither); no claim applies to those configurations. A complete wall-time deadline needs audited interruptible native operations or refusal of unbounded inputs, and cannot be established from an external harness timeout.

Dependency impact: only pinned RustPython VM fork and consumers, no Python process/runtime wrapper, no renderer changes. The hook is an investigation proposal requiring source review and dedicated tests before adding vendor source or production run_python.
