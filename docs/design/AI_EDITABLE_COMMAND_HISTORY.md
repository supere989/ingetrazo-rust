# Command-owned editable mesh history design

Production remains disabled. Actual frozen source SnapshotImport captures root membership and mutable Vertex/Edge/Face fields, then restores SAME mesh objects but NEW position/loop/attrs wrappers on Undo and Redo. Shared nested attribute values remain aliased even through Undo. Its raw QVector edits preserve old registry key ownership; move_vertex/place_vertex update keys separately. Direct loop edits do not rebuild the radial graph. These are distinct operations, not one blanket topology-heal rule.

The next controller implementation needs immutable identity snapshots with shallow arbitrary-Python attribute handles and numeric position values. Restore must prepare NEW VM wrappers from immutable templates on every invocation, never expose or reuse stored template wrappers. History owns before/after templates and logical leases; allocation refusal must retain both command stacks. A successful existing-field operation must reserve after-state/history slots before native publication. Snapshot equality must follow actual Python equality and source shallow alias behavior; callback effects and native execution cost remain an explicit prerequisite.

Native command routing must preserve chronological append and raw-field commands. A raw-field undo should prepare spatial publication and restore the native owner's prior state token without reviving held registry Views: monotonically increasing revision still invalidates every old View. This allows a preceding append command to undo/redo with its real ownership. Reordering/deleting arbitrary Vertex/Face membership needs persistent object-ID mappings and identity-based radial/end-point remapping; count-only validation is unsafe. Mixed existing edits plus staged appends require a unified prepared ticket and cannot be silently split into committed phases.

Currently the bounded unchanged-membership ticket refuses order/replacement and mixed append cases. Staged identity handles also validate newly-created rings/positions before any native append. Those refusals are temporary safety boundaries, not final source parity or permanent scope exclusions. All edge/face/group helper APIs, actual Scene/adoption history, general arbitrary Python object mutation, external handles, compiler/native allocation/callback/deadline bounds remain required.
