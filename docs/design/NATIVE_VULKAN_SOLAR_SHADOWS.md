# Native Vulkan solar shadows: staged consumer

The selected native application consumer calls `solar_controls::scene_direction`, using the loaded date/zone, actual local year and scene datum. Invalid dates/night/disabled/sheet rendering disable shadows without modifying document settings. The application selects this consumer through its existing shadow setting on the native World path; this is a Partial implementation, not a completed P20 claim.

A persistent 2048x2048 RGBA8 packed-depth/D24 target is rendered camera-independently. Immutable scene geometry and sampled cutout textures are reused; HiddenLine/Monochrome use a separate cached caster packet because their receiver geometry intentionally loses cutouts. Front opacity below .7 does not cast. Missing external textures cast solid and omit the unavailable sampled receiver. Malformed embedded assets continue to refuse transactionally. The map is nearest/clamp sampled, and uses the original slope offset, packed depth, 3x3 receiver-plane PCF and bias. Ground is z=-.005, blended before faces without depth writes. Translucent and explicit back overrides remain unlit, matching the source uniform reset before those passes.

Sun/section/bounds/scene identity invalidate the map; camera-only changes do not. Uniform/ground/caster candidate allocations and retirement are admitted before publication. New shadow preparation is aborted if the World candidate fails; existing Ready resources remain together. Before starting the map pass all referenced buffer and texture IDs are admitted. Off/on preserves the map. Unknown GPU completion retains the native owners through the existing Lifetime quarantine; no CPU image rendering or process converter is introduced.

The diagnostic may request one sample and map TRANSFER_SRC; normal production still selects its existing multisample target and has no diagnostic transfer usage. Actual original Qt/NVIDIA paintGL reports zero samples; one-sample comparison does not validate the production four-sample scene path.

Sun-facing bitmap casters use a separate retained sprite vertex packet. Sun-only changes replace only that packet, preserving ordinary geometry, images and descriptors. Mesh face-me groups do not cast. Ground is suppressed for visible terrain and a visible base map with scene datum. There is no typed native photo renderer readiness API, so photo suppression remains unimplemented rather than inferred from metadata counts.

Remaining required scope: photo ground suppression, real application setting/presentation acceptance, source clipping packed-depth precision, complete receiver frame equality, default multisample and alternate-device/Metal parity. The actual original offscreen-instance corpus has no visible changed receiver pixels, so exact output there proves map inclusion and baseline, not a positive visible offscreen shadow. No throughput claim is made from pass count.
